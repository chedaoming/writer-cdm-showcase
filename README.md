# Writer-CDM · AI 长篇小说质量控制与生成平台（展示版）

**一句话：不是「让 AI 写小说」，而是「让 AI 写得稳定、可评估、可控」。**

> 本仓库是**脱敏展示版**：只保留架构说明、类型骨架与评测方法。完整工程代码、知识库数据与评测语料在私有仓库中，未公开。本仓库不含任何第三方小说原文、付费内容或个人数据。

## 为什么做这个

生成式长篇写作有三个硬问题，靠调提示词解决不了：

| 问题 | 典型表现 | 本项目的处理 |
| --- | --- | --- |
| 设定漂移 | 写到十章后人物性格、称呼、世界观前后矛盾 | 分层上下文构建 + 步骤级字段策略（FIELD_POLICIES） |
| AI 味 | 套话、情绪堆叠、句式单一 | AI 痕迹词典 + WR-Scan 量化规则 + 修订轮次收敛 |
| 评分不可信 | 模型自评分数虚高、区分度低 | 六维评分 + LLM-as-Judge 与人工打分校准，代码兜底 |

## 架构总览

1. **多 Agent 写作流水线**：大纲师、角色师、剧情师、润色师分工协作，逐步产出蓝图、章节与修订稿。
2. **六维评分体系（AuditScores）**：反转 twist、情绪 emotion、逻辑 logic、角色 character、节奏 rhythm、人味 humanity，代码规则与 LLM 评分混合加权。
3. **知识库**：17 个子类的规则、结构框架、风格模板、角色原型，另有 AI 痕迹词库与平台合规规则；770 个题材到工序的精确映射。
4. **校准闭环**：48 篇样本横评（多模型 + 人工打分），量化每个维度的相关系数与平均误差。
5. **工程化**：断点续跑、模型失败自动降级、token 预算与配额控制、审稿上下文压缩。

## 校准结论（真实实验数据）

- 逻辑一致性 r≈0.96，情绪 r≈0.87，人味 r≈0.81；节奏维度代码侧区分度偏低，需 LLM 补位。
- LLM 自一致性复测（同一模型两次运行）：Overall r≈0.30，维度平均差约 1.0 分。
- 结论：**「给小说打分」这件事本身的天花板约在 r≈0.3**，因此系统设计为「LLM 为主评分 + 代码兜底 + 人工抽检」，而不是让模型自由打分。
